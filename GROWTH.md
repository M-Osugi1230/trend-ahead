# Trend Ahead — Public Launch / Growth Strategy v0.3

## Core promise
「明日の話題を、今日知る。」 / 「あとで知って後悔」を減らす。

## Growth loop (UI implemented; analytics not yet instrumented)
1. Discover: long-tail searches about tonight's plans or tomorrow's likely topics, and original posts shared on X.
2. Activate: find one relevant candidate, view its provenance and first-detection time, and click through to the original.
3. Retain: revisit; browse personalized categories; save items for later. Future: opt-in digest and notifications.
4. Refer: share a **specific** story page with a friend. The link is shareable, but autogenerated story pages are `noindex`.
5. Improve: assess misses and whether the early signal led to enjoyment, without optimizing to clicks alone.

## Initial acquisition channels (hypotheses, not observed performance)
| Channel | User intent | Public asset | Instrumentation needed |
|---|---|---|---|
| SEO: service/intent | トレンド 先取り、今夜の話題、今日何が話題 | Homepage, How, Methodology | Google Search Console queries, CTR |
| X sharing | 「この話題、まだ知らなかった」 | Per-topic page with first observed time and source link | Share clicks, inbound referrals |
| Niche communities | Gaming, sport, animation, livestreams | Relevant filters and original contextual guides (future) | Referrer, scroll, return sessions |
| Direct return | Habit: morning / evening check | Homepage + saved items | Anonymous returning sessions / opt-in survey |

Search volume and SEO demand **have not been validated**. Do not claim that these keywords already produce traffic.

## Editorial rules
- RSS candidate ≠ popularity forecast. Label only as observed; never assign invented "80% likely to trend" scores.
- Do not crawl or republish article bodies; link to sources.
- Auto-generated topic pages must be `noindex` even if users can share direct links. Reserve indexed pages for original analysis with source verification, up-to-date context and concrete participation options.
- Keep disasters, violence and sensitive events out of entertainment-style recommendations; define a separate safety policy before push notifications.
- Upcoming editorial entries require verified start time, official HTTPS link and verification timestamp.
- Do not add fake waitlist buttons or collect emails without a real backend, consent, privacy information, and anti-abuse controls.

## Experiments for the first 2 weeks after launch
- **E1 (SEO)**: measure verified Search Console impressions and clicks. Baseline is zero until live property confirmed; no traffic projection.
- **E2 (sharing)**: share hand-picked, genuinely informative topic links in a context where self-promotion is permitted. Measure visit-to-source-click, not only pageviews.
- **E3 (activation)**: ask 20–30 voluntary testers whether a timely discovery resulted in a useful or fun experience. Survey target is an experiment design, not a claimed achieved count.
- **E4 (coverage)**: every day, compare user-reported missed trends to RSS observations. Distinguish ingestion gap, clustering gap, ranking gap and notification gap.

## Metrics definitions (to implement with privacy-conscious analytics)
- `organic_sessions`: search-engine referred visits (provider-reported, no identity collection required).
- `source_open_rate`: original-source outbound clicks / topic page sessions.
- `save_rate`: sessions saving one or more topics / landing sessions.
- `share_rate`: sessions opening a share dialog or copying a link / topic sessions.
- `useful_discovery_rate`: opt-in positive feedback / total opt-in feedback.
- `early_hit_rate`: eligible stories surfaced before their observed external peak / evaluated stories (requires longitudinal data and careful peak definition).
- `missed_opportunity_rate`: user-reported missed topics / all topics a user retrospectively wished to join.

None of these metrics are currently connected to a live analytics backend. Do not display invented numbers.

## Release criteria
- [ ] Own new repo, enable Pages, confirm deployed URL loads and public source links work.
- [ ] Verify >1 real RSS ingestion runs at different times, validate recency and failures.
- [ ] Set final `SITE_URL` to canonical HTTPS URL and confirm all navigation and share links under project path.
- [ ] Add verified operator/contact details (and final privacy policy) before public promotion.
- [ ] Search Console ownership, sitemap validation; verify noindex on autogenerated topic pages.
- [ ] Mobile browser QA, load/performance/accessibility, error logging.
- [ ] Add transparent privacy-safe event analytics before experimenting on conversion.
- [ ] At least a handful of *verified* upcoming events in popular categories (otherwise future-trend proposition remains partial).
- [ ] Review naming/trademark/domain before brand launch.

## Monetization later
Keep core free until value and repeat visits are demonstrated. Potential premium options: granular early-warning alerts, calendar reminders, custom interest profiles. Do not gate core discovery prematurely.


## Phase 1.2 implementation update (2026-11-15)
- Added interest categories stored locally and an optional 3:1 interest/discovery ordering to keep recommendations broad; no cloud profile.
- Added a weekly verified-events page and a multi-event `.ics` feed as a no-login retention mechanism.
- Added RSS subscriptions for observed topics and upcoming events when a canonical URL is set.
- Added independent collection-health status, so an hourly static build does not imply fresh ingestion.
- Search indexing has an explicit gate (`PUBLISH_READY=1` plus a valid `OPERATOR_CONTACT`) and is disabled by default.
- 15 Python unit tests plus browser interaction checks passed in development. Real RSS/live hosting/real-user acquisition are **not yet verified**.
- Full evaluation definitions in `METRICS.md`.
